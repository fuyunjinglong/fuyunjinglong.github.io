# 初级

## Monorepo是什么

**1.定义**

Monorepo（单体仓库）是一种将多个相关联的项目、模块或包放在同一个代码仓库中进行管理的软件工程策略。
它打破了传统的 Multi-repo（多仓库）模式，核心目的是通过**统一的工作流、共享的工程配置和简化依赖管理**，来提升大型前端项目的代码复用率和团队协作效率。

**2.核心优势**

相比于 Multi-repo，Monorepo 解决了以下痛点：

1. **代码共享与复用极度方便：** 组件库、工具函数、类型定义可以直接跨项目引用。不需要发布到 npm 仓库，源码级别的引用让重构和调试更加容易。
2. **原子化提交与一致性：** 当进行跨项目的重构或修复底层公共组件 Bug 时，可以在一个 PR/Commit 中同时修改多个项目，保证了各个项目之间代码的强一致性，避免了版本碎片化。
3. **统一的工程化配置：** 项目的 ESLint、Prettier、TypeScript 配置、CI/CD 流水线可以放在仓库根目录统一管理，降低了多仓库下的维护成本。
4. **依赖提升与管理优化：** 公共的第三方依赖可以提升到根目录统一管理，避免了不同项目安装不同版本导致的冲突，同时大幅节省了磁盘空间和安装时间。

**3.劣势**

虽然优势明显，但 Monorepo 也会引入新的工程化挑战：

1. **CI/CD 构建变慢：** 随着项目增多，如果每次提交都全量构建和测试所有项目，会极大地拖慢流水线。
2. **权限控制困难：** 所有代码都在一个仓库中，Git 原生的分支权限难以做到“限制某些开发者只能修改特定的子项目”。
3. **Git 体积膨胀：** 所有的历史记录和资源都在一个仓库，随着时间推移会导致仓库体积变大，影响 `clone` 速度。

**4.常用工具链与技术选型**

在实际落地 Monorepo 时，通常分为“包管理”和“任务编排”两层：

1. 包管理工具：pnpm Workspaces（当前最优解）
   - 相比 Yarn 和 npm，pnpm 使用了软链接机制，能极大节省磁盘空间。
   - **防幻影依赖：** pnpm 严格的 `node_modules` 结构，阻止了项目引用未在 `package.json` 中声明的包，让 Monorepo 的依赖关系更加健康。
2. 构建与任务编排工具：Turborepo / Nx
   - **Turborepo：** Vercel 出品，核心优势是**内容寻址缓存**和**增量构建**。它能记住之前的构建结果，如果代码没变，直接秒级返回缓存，大幅提升 CI 速度。
   - **Nx：** 功能更强大，支持依赖图分析，能精确知道哪些项目受影响，并提供丰富的插件（支持 React, Vue, Node 等）。
   - *(注：Lerna 曾经是标配，但目前已逐渐被 Nx 和 pnpm 替代。)*

**总结**

Monorepo 不是银弹，它用“仓库体积”和“工具复杂度”换取了“开发效率”和“代码一致性”。

- 如果是**初创团队或小型团队**，维护少量项目，Multirepo 足够简单有效。
- 如果是**中大型团队**，面临多个产品线共享组件库，或者需要频繁重构公共基础建设，Monorepo 配合 **pnpm + Turborepo** 是目前的最佳实践。

**💡 面试技巧提示：**
如果面试官追问 *“pnpm 相比 npm/yarn 在 Monorepo 中有什么绝对优势？”*
你可以回答：**“核心在于解决了‘幻影依赖’问题。npm/yarn 的扁平化 `node_modules` 允许项目使用未在 `package.json` 中声明的包，这在 Monorepo 中会导致依赖关系混乱、打包报错。而 pnpm 采用非扁平化的软链接结构，严格限制了包的访问范围，强制开发者显式声明依赖，这让大型 Monorepo 项目的稳定性得到了质的提升。”** 这会极大展现你的实战经验和底层原理认知。
